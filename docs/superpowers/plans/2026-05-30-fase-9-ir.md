# Fase 9 — Calculadora de IR (renda variável) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) ou superpowers:executing-plans para executar task-a-task. Steps usam checkbox (`- [ ]`).

**Goal:** A partir do histórico de transações (paper trading), apurar mensalmente o IR de renda variável — ações (15%, com isenção de R$ 20k/mês) e FIIs (20%, sem isenção) — com preço médio, compensação de prejuízo e DARF; exibir em uma `ScreenIR` acessível via Profile. **Caráter educativo/simulação** (não substitui apuração oficial).

**Architecture:** Motor puro `src/lib/ir.ts` (sem I/O) consome `Transaction[]` + a classificação ação/FII por ticker e devolve um relatório mensal/anual. `ScreenIR` lê `useTransactions` + `useStockQuotes` e renderiza. `Transaction` ganha `assetType` (capturado na criação; fallback para transações legadas).

**Tech Stack:** React 19 + TS strict, Vitest, inline styles + `PraxiaTokens`, lazy-load + Suspense (padrão das telas via Profile).

**Depende de:** Fase 8 (FIIs) — a distinção ação/FII é o que separa as duas regras fiscais.

## Regras fiscais (BR, pessoa física) — o que o motor implementa

**Ações (operações comuns / swing trade):**
- Lucro tributado a **15%**.
- **Isenção:** se a soma das **vendas de ações no mês ≤ R$ 20.000**, o lucro dessas vendas é **isento**.
- **Prejuízo** compensa lucros futuros de renda variável (mesma categoria), sem prazo.
- Custo = **preço médio ponderado**; lucro da venda = `(precoVenda − precoMedio) × qtd − taxas`.

**FIIs:**
- Ganho de capital na venda de cotas → **20%**, **sem** a isenção de R$ 20k.
- **Prejuízo de FII** compensa **apenas** lucros de FII (categoria separada).
- Rendimentos mensais (distribuições) → isentos de IR para PF — **fora do escopo** deste cálculo (o app não modela distribuição como evento tributável; só ganho de capital na venda).

**DARF:** imposto apurado por mês; **dispensado se o total devido no mês < R$ 10** (sinalizado, não recolhido). Código 6015. Vencimento: último dia útil do mês seguinte.

### Decisões/simplificações assumidas (ajustáveis)
1. **Tudo é swing trade / operação comum.** Paper trading não distingue day trade; não aplicamos a alíquota de 20% day-trade nem separamos essa categoria. (Aviso na tela.)
2. **Isenção 20k**: aplicada ao **lucro** de meses cujas vendas de ação ≤ 20k. Prejuízo sempre entra no estoque de prejuízo a compensar (não tratamos a vedação de compensar prejuízo de operação isenta — simplificação documentada).
3. **DARF < R$10**: sinalizamos "abaixo do mínimo, não recolher" e **não** carregamos o imposto pro mês seguinte (simplificação; a regra real acumula). Documentado.
4. **Preço médio ponderado** recalculado a cada compra; venda não altera o preço médio (só reduz quantidade). Vender mais do que a posição (dado inconsistente de paper trading) → ignora o excedente e loga aviso no resultado.
5. **Taxas (`fee`)** entram no custo da compra e abatem o ganho na venda.
6. **Disclaimer obrigatório** (CVM/educativo) no topo da `ScreenIR`, reusando o tom de `CVM_DISCLAIMER`/SIMULAÇÃO já existente.

```ts
export type IRCategoria = "acao" | "fii";

export interface IRCategoriaResultado {
  /** Soma das vendas (R$) da categoria no mês. */
  vendas: number;
  /** Resultado realizado no mês (lucro>0 / prejuízo<0), já líquido de taxas. */
  resultado: number;
  /** Prejuízo acumulado disponível ANTES deste mês. */
  prejuizoAnterior: number;
  /** Base tributável após compensar prejuízo (>=0). */
  baseTributavel: number;
  /** Imposto da categoria no mês (R$). */
  imposto: number;
  /** Para ações: true quando vendas<=20k → lucro isento. */
  isento: boolean;
  /** Prejuízo a transportar para o mês seguinte. */
  prejuizoAcumulado: number;
}

export interface IRMes {
  /** "2026-03". */
  mes: string;
  acao: IRCategoriaResultado;
  fii: IRCategoriaResultado;
  /** Soma dos impostos das categorias. */
  impostoTotal: number;
  /** true se impostoTotal < 10 (DARF dispensado no mês). */
  darfDispensado: boolean;
  /** Avisos (ex.: venda sem posição). */
  avisos: string[];
}

export interface IRReport {
  meses: IRMes[];
  /** Imposto total do período. */
  impostoTotalPeriodo: number;
  /** Prejuízo a compensar no fim do período, por categoria. */
  prejuizoFinal: { acao: number; fii: number };
}
```

- [ ] **Step 3: Implementar `src/lib/ir.ts`.** Estrutura:
  - `export interface IRClassify { (ticker: string): IRCategoria }` (ou `(ticker)=>"acao"|"fii"`).
  - `export function calcularIR(transactions: Transaction[], classify: (t: string) => IRCategoria): IRReport`.
  - Algoritmo:
    1. Ordena transações por `timestamp` asc.
    2. Mantém por ticker: `{ qtd, custoMedio }`. Compra: `custoMedio = (qtd*custoMedio + shares*price + fee) / (qtd+shares)`; `qtd += shares`. Venda: `resultadoVenda = shares*price − fee − shares*custoMedio`; `qtd -= shares` (se `shares>qtd`, usa `qtd`, registra aviso, zera). Categoria via `classify(ticker)` (ou `tx.assetType` quando presente — preferir `assetType`, cair em `classify` se ausente).
    3. Agrega por mês (`YYYY-MM` do timestamp UTC) e por categoria: soma `vendas` (só de SELL) e `resultado`.
    4. Pós-processa meses em ordem: para cada categoria, `prejuizoAnterior` vem do mês anterior; se `resultado>0`: ação isenta quando `vendas<=20000` (imposto 0, prejuízo anterior **preservado**); senão `base = max(0, resultado − prejuizoAnterior)`, `imposto = base * (acao?0.15:0.20)`, `prejuizoAcumulado = max(0, prejuizoAnterior − resultado)`. Se `resultado<=0`: `imposto 0`, `prejuizoAcumulado = prejuizoAnterior + |resultado|`.
    5. `impostoTotal = acao.imposto + fii.imposto`; `darfDispensado = impostoTotal>0 && impostoTotal<10`.
    6. `impostoTotalPeriodo` = soma; `prejuizoFinal` = último prejuízo acumulado por categoria.
  - JSDoc no header (estilo `fiiScore.ts`), `import type { Transaction, IRReport, IRMes, IRCategoria, IRCategoriaResultado } from "@/types/stock"`.
